## 产品目标

用户浏览 `asmr.one` 的作品海报或详情页时，不必复制 RJ 号，即可：

1. 看见作品是否已经存在于 ARSM 资源库；
2. 将未入库作品交给 ARSM 的现有下载器；
3. 看见已排队、下载中、失败和已入库等状态；
4. 在 ARSM 设置页完成扩展安装引导、连接检查和卸载引导。

浏览器扩展只负责识别 RJ、展示状态和提交指令。下载、重复检查、队列、文件写入和错误处理继续由 ARSM 负责。

## 第一阶段：协议和安全边界

- [x] 记录 `asmr.one` / `www.asmr.one` 支持范围、页面结构和 RJ 提取规则；
- [x] 定义本机桥接 API，只监听 loopback，不暴露到局域网；
- [x] 为扩展生成独立令牌，并限制允许的扩展 ID 和请求来源；兼容 Chromium MV3 opaque Origin 时仍强制校验扩展 ID 与令牌；
- [x] 定义 `health`、批量查询入库状态、提交下载、查询任务状态四类接口；
- [x] 只向扩展返回 RJ、业务状态和安全错误码，不返回绝对路径、Cookie 或内部对象；
- [x] 复用现有 RJ 标准化、`find_in_library`、`queue_job` 和队列去重逻辑；
- [x] 明确 ARSM 未启动、扩展未连接、令牌失效、作品已入库、任务已存在的行为；
- [x] 添加速率限制、请求大小限制和结构化日志脱敏。

完成标准：本机接口单元测试通过；非 loopback 请求、无令牌请求、伪造来源和非法 RJ 全部被拒绝。

## 第二阶段：浏览器扩展 MVP

- [x] 创建 Manifest V3 扩展；
- [x] 在海报列表的销量区域右侧显示 `已入库`、`未入库` 或 `ARSM 未连接`；
- [x] 为未入库作品显示紧凑的“下载到 ARSM”按钮；
- [x] 在作品详情页销量区域显示明显的“使用 ARSM 下载”按钮；
- [x] 点击后显示 `已排队`、`下载中`、`失败` 或 `已入库`；
- [x] 已入库作品默认显示“在 ARSM 中打开”，不提供主操作重复下载；
- [x] 同一页面批量查询状态，避免每张海报单独请求；
- [x] 使用 MutationObserver 处理站点的动态加载和翻页，避免重复注入按钮；
- [x] ARSM 未运行时给出可理解的启动提示，不把未连接误报为未入库；
- [x] 站点 DOM 变化时安全降级，不影响原网页浏览。

完成标准：列表页、搜索页和详情页可见状态正确；重复注入为零；按钮不会遮挡销量、标题或海报操作。

## 第三阶段：ARSM 设置页管理

- [x] 新增“浏览器扩展”设置分区；
- [x] 显示桥接服务开关、连接状态、端口和令牌状态；
- [x] 提供“打开安装目录”和逐步安装说明；
- [x] 提供“检查连接”和“重新生成令牌”；
- [x] 提供卸载引导并允许停用本机桥接服务；
- [x] 说明浏览器安全限制：应用不能静默安装或卸载扩展；
- [x] 设置保存和重启后的状态一致。

完成标准：代码小白也能按设置页指引完成安装、连接检查和停用；应用不会假装已经替用户安装浏览器扩展。

## 第四阶段：下载体验和恢复

- [x] 点击下载默认只加入 ARSM 队列，不在扩展中实现下载器；
- [x] 已在队列、下载中或已入库时阻止重复提交；
- [x] 失败状态提供“在 ARSM 中查看”或受控重试；
- [x] ARSM 重启后扩展重新同步状态；断开时每 10 秒低频重试；
- [x] 浏览器刷新和多标签页不会产生重复任务；
- [x] 下载完成后标签自动切换为 `已入库`；
- [x] 将“允许重复下载”保留为 ARSM 内部高级操作，并要求确认。

## 暂不包含

- 内建完整浏览器；
- 绕过站点登录或复制浏览器 Cookie；
- 浏览器扩展直接写入媒体目录；
- 自动重复下载已入库作品；
- 支持未审计的第三方站点；
- 修改现有下载器架构或数据库 schema。
